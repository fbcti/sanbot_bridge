WebSocket Console

Sanbot Bridge WebSocket Explorer

A browser-based WebSocket explorer for the new bridge. Connect, load example commands, send JSON messages, and watch responses and push events arrive in one place.

Recommended protocol shape: {"id":"req-1","type":"command","module":"speech","action":"say","data":{"text":"Hello"}} for commands, and {"id":"req-2","type":"info","module":"bridge","action":"status","data":{}} for read-only info requests. Responses use {"type":"response","id":"req-1","code":0,"message":"OK","data":{...}} and pushed events use {"type":"event","id":"evt-1","module":"head","event":"pressed",...} .

Protocol Notes

  • The first privileged message should be {"type":"command","module":"bridge","action":"authorize","data":{"key":"..."}}.
  • The first authorized active socket receives read_write; later authorized sockets are read-only until promoted.
  • Commands should include id, type: "command", module, action, and a data object.
  • Read-only requests use type: "info"; handler-backed requests cover bridge OpenAPI/status, sensor orientation/infrared, camera features, audio volume, speech features/status, and battery status.
  • Responses mirror the request id and include type: "response", numeric HTTP-like code, and message. Successful handler requests use codes in the 2xx range, usually 200.
  • Push events arrive with type: "event", plus module, event, and data.
  • Head touch callbacks are surfaced as module: "head" with the touch sensorId inside data.
  • Movement commands use data.direction for values like left or forward; head:move accepts all head directions, while head:turn and head:nod restrict that direction to one axis.
  • Binary camera images and MJPEG streams are available only through the REST API.
  • Screen images use command:screen:image with a file name relative to /sdcard/SanbotBridge/images; omit data.filename to show the main bridge window.
  • Audio playback uses command:audio:play with exactly one of data.url or data.filename; local audio files are relative to /sdcard/SanbotBridge/audio.
  • Audio capture starts with command:audio:record using data.length in seconds; recorded WAV data is retrieved through the REST API.
